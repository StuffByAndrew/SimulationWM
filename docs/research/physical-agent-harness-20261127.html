Which harness changes would help agents learn physics?

Build a way to turn an interaction into a repeatable test, then use competing models to decide which interaction to try next. The agents already write fitting code and run local simulations. They can recover millimetre-scale geometry and still miss the event that governs what an object does. Other agents spend an entire session describing actions they never execute. These failures need different interventions.

The first 3D tool worth building is a measurement pipeline that returns an editable collision model, the observations supporting it and the places where more sensing would help. A learned mesh can be one input. The criterion for success is whether a model built with the tool predicts new contacts, motions or manipulations more accurately for the same resources.

What to build, in order

1. A regression suite for the agent's experiments

Give the agent one operation to save a physical experiment and another to compare its candidate versions. A saved experiment contains the exact public actions, units and coordinate frames, starting observations, timestamps and cumulative ticks, a candidate hash, expected observable events and the actual replies. Preserve negative results and the last successfully executed action of a partial sequence. Store the detailed evidence in the workspace and return a short comparison with links to the raw observations. A useful result on the hand is “new candidate makes contact at step 21, reference stays unloaded through step 24.”

The agent chooses some identification episodes for fitting and reserves whole, differently directed or differently loaded episodes for checking. It can compare the current candidate, its previous submitted version, and a simpler alternative before submitting. Show the first divergent event and the largest residual by channel in physical units. Show the retained version alongside the revision if one improves static shape and the other better predicts release. This makes regression and incomplete coverage visible without choosing the agent's scientific objective for it.

Existing integration point. The prompt already asks for hypotheses, matched experiments and notes. sequence already executes an agent-authored list in one world and saves non-image observations. LocalController runs the hand agent's own scene, and Channel exposes permitted reference operations on tasks that enable it. Extend these with a versioned trace, a comparison command and an index that survives context compaction. Record only frames/calibration the public interface delivers, with explicit bounds. Dispatch any additional reference observation through the usual controller and accounting. Candidate-only replay can reuse an observation the agent has already paid to obtain. Harness and compaction · Worlds, sequence, local controller and channel.

Coding precedent. SWE-agent raised GPT-4 Turbo's resolved rate on SWE-bench Lite from 11% with a shell to 18% with a purpose-built interface. That comparison bundles several changes. Agentless provides a more specific transfer mechanism. It generates a test that reproduces an issue and uses that test together with existing regression tests to select a patch. A failed tilt or false fingertip contact can play the role of a failing software test. Anthropic's long-running coding-agent work also describes using progress records and recoverable versions across context windows. Here the durable record should point to measured evidence and candidate versions. Yang et al., SWE-agent, Table 1 · Xia et al., Agentless, §3.3 · Anthropic, long-running harness engineering case study.

2. A probe selector that tries to disprove the current model

Let the agent supply two or more candidate explanations and a few action programs. For each program, simulate what each candidate predicts the public sensors would show. Rank programs by between-candidate disagreement, relative to repeat noise, time and risk of changing the setup irreversibly. Show which observable separates which candidates. Run one chosen program on the reference and update the comparison. A probe that predicts indistinguishable signals across candidates has little value for selecting between them.

Start with unit-checked programs for a ramp followed by a hold, a reversal, the same excursion at a second speed, a repeat cycle, a tilt followed by settling, and a crossed pair of motion axes when the embodiment supports it. The same programs can distinguish a velocity-dependent force from a position-dependent one, a moving load from a fixed one, or a response that depends on prior actions. Let agents write their own programs on the allowed channel. A threshold such as “until load changes” can depend only on a sensor actually enabled in that run. Keep raw readings and report actuator travel at the onset of contact so the agent can distinguish a jam from a spring measurement.

Inspect a local model's parameter sensitivity on those same observation traces. A nearly flat direction is worth reporting as a range or parameter ratio. It is a local numerical diagnostic. A structural ambiguity, such as scaling inertia, damping and spring stiffness together in passive motion, can also be checked analytically. No fitting routine can supply an absolute scale absent from the experiment. If all candidate models share a mistaken assumption, their mutual agreement can be misleading. Include a small allocation for untried action regimes and a simple competing model, even when the predicted disagreement is small.

For reset-free work, begin from the measured current condition, carry uncertainty about a displaced object, and try reversible probes before those likely to remove it from reach. Replay a previously observed trace against candidate starts consistent with that observation. A reference rewind, state clone or virtual reset would change the experiment. In real time the physical clock and stream deadline still govern all actions and inference. Reset-free trace evidence · Live-world contract.

Research precedent. Kruzliak et al. selected real robot manipulations by expected information gain over uncertain physical properties. Swevers et al. designed excitation trajectories to reduce parameter uncertainty on an industrial robot. Shyam et al. used forward-model disagreement for directed exploration. Liang et al. demonstrated executable feedback policies on multiple robots. These works support specific choices of probe and interface. They assume candidate models, calibrated actions or observations that a sim2sim agent must construct from its own evidence. Wave 16 shows why a convenient action sequence alone can still miss the phenomenon. Kruzliak et al., interactive property measurement · Swevers et al., optimal robot excitation · Shyam et al., model-based active exploration · Liang et al., Code as Policies.

3. A 3D measurement tool that produces testable collision geometry

The output should be useful in the agent's next action or candidate edit. Return an object-relative point set or surface with units, the views or touches supporting it, unresolved regions, a short list of fitted collision shapes in an explicit frame, and a reprojection or contact comparison for each fit. Let the agent export an editable MJCF fragment with geometry and poses. Assigning mass, inertia or friction requires separate evidence. Save large arrays locally and put the comparison and a preview in the model's context. Start with NumPy/SciPy and the installed simulator on CPU.

4. A recovery path for models that describe actions without issuing them

This is the highest-priority intervention for Inkling. The existing harness already tells the model when it has made no tool call. A repeated prose reminder has been tested in practice. After consecutive ordinary work turns with no executable call, offer a constrained action turn using the actual public action schema. Validate once, execute exactly the selected valid operation, and return the result. Preserve intentional finish, legitimate text-only compaction and the existing submission and finish semantics. Record malformed output, valid but rejected actions, repeated valid actions with no progress, and tool-free prose separately.

Grammar-constrained decoding can enforce shape but cannot select a useful experiment. The decisive metric is the fraction of runs with a valid, scientifically useful submission and its held-out quality. A model that generates syntactically perfect camera calls for four hours has gained little. Test the self-hosted model and a strong reference model separately, including the latency of any recovery calls inside the original budget. Current no-call handling · Five Inkling traces · Dong et al., XGrammar.

5. Two small extensions for different deliverables

For scene reconstruction, audit the agent's own compiled model. List movable and world-fixed bodies, each body's mass and collision geometry, resolved joint types, inertia and units. Let the author declare which body is the support or target in its own model, compare a simple model against a detailed one on its public experiments, and see runtime per simulated second. A mistakenly free support or a mesh whose convex collision surface fills a hollow opening should be visible before submission. Any threshold that uses the true source mass or source labels belongs exclusively to the researcher. The spring-table misassignment and the gear cost/removal trade-off are distinct reasons to build this. Model complexity should be determined by the stated use. Cube measurement caveat · Gear tasks · Sturm et al., probabilistic selection of articulation models.

For predictors, give the agent a trial table. Record public dial readings or launch protocol, repeat number, the outcome the agent could measure from its own images, and prediction made before that outcome. Fit an empirical baseline per setting, reserve entire settings or throws, and compare the distribution with CRPS or Brier. For the die, play the public frame prefix into the agent's predictor at the actual cadence and measure latency. In the fixture the agent must read the carriage against the ruler. Its trace already describes fitting 162 releases at 24 settings and leave-one-setting-out analysis. A general wrapper is valuable if another model can reach similar calibration sooner, or if it improves coverage of a second mode. Give the simple mean or frequency baseline the same data, and evaluate on fresh private trials. Bimodal fixture run · Held-out scores · Gneiting & Raftery, proper scoring rules.

Experiments that could verify or overturn the recommendations

First test I would fund. A 12-run strict pilot of the regression suite on the two-cone hand and an unhinted inside-start tunnel. For each level, pair the current harness and the new suite on three independently run scene/agent blocks with fresh contexts. Keep the existing local controller available in both hand arms. Pick one model, such as Neon, for this comparison. The proposed primary outcomes are private squeeze/tilt object-path error in millimetres and normalized force-profile error respectively. These tasks test distinct failures with the same component. A positive pilot earns a transfer test. Three pairs give a variance estimate and examples to diagnose, with limited precision for the treatment effect.

Comparability, leakage and the decision to ship

  1. Pair and replicate. Match source hash within an A/B block, camera/sensors, reset rules, prompt information, available prior knowledge, provider route, model version, reasoning level, output cap, sandbox limits and resource budget. Counterbalance execution order across time and nodes. Start each run with a fresh agent workspace and context. Repeats on the identical scene measure agent variance. Fresh parameter, pose, topology or contents variants measure transfer. Hold an entire mechanism family and a second model out of tool design. Existing benchmark families are familiar to the researchers, so freeze the component before generating the confirmatory variants.
  2. Keep agent and researcher evidence distinct. New tools operate inside the strict public boundary, on observations already returned by the controller, permitted actions, public robot kinematics, and the agent's own candidates. No source model, ray hits, hidden body IDs/poses, contact points, actual COM, evaluator code, score, script, seed, or archived hidden state enters the agent. Agents with the same public contract get the same probe menu. A level ID, undisclosed object count or mechanism-specific hint in a tool description would compromise an unhinted comparison. A blind, fixed-camera, force-free, no-interaction or no-reset condition must retain that restriction through every helper. A tactile helper may use an enabled taxel footprint without producing a source contact location. Replaying an agent-owned candidate is distinct from rewinding the reference. Verify modality removal in the actual tool responses and mounted files. Public interface · Verified archived playback · Researcher-only evaluation.
  3. Charge the intervention. Keep normal cumulative reference and reconstruction accounting. Log candidate simulations, CPU/GPU seconds, wall time, reference actions and ticks, model calls, tokens and any service latency for all arms. Publish last available checkpoints at matched run minutes and matched cumulative provider-counted tokens, including Astra's stopping budget. Record time to first useful submission and time to a prespecified threshold. A run with no checkpoint by a cutoff contributes a failure to submission/threshold attainment and a missing conditional error. Retain an agent's final submitted model if it finished early. Separate provider outages, malformed replies, budget suspensions and voluntary finishes. Keep spend and caps on the researcher side.
  4. Measure a predicted benefit and an opportunity cost. Preselect one physical primary outcome and a practical threshold per family before looking at the new runs. Show paired absolute effects in native units and all paired points. Report uncertainty over independent run/scene blocks, preserving the pairing, and list denominators at every budget. Use a blocked interval or hierarchical resampling with sufficient independent blocks. Avoid ratios when baseline error is near zero. Keep object discovery, valid submission rate and runtime as guardrails. Agarwal et al., evaluation under few-run uncertainty.
  5. Make a prospective decision. My proposed bar for broad rollout is at least a 25% reduction in the prespecified non-ceiling behavioral error on two held-out families at equal budget, replicated across two model families, with an interval supporting improvement and no material loss in submission or discovery. Size confirmation from paired pilot variance and this practical effect. For a speed tool, predeclare a time-to-target improvement and a physical-quality noninferiority margin instead. For Inkling, first establish that a material fraction of runs make useful submissions. Keep a component scoped to its modality or model when that is what the evidence supports.
