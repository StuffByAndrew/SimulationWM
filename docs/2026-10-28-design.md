# sim2sim design — 2026-10-28

## Goal
Evaluate a sandboxed agent's ability to reconstruct an object environment from a predefined camera and permitted interactions. The researcher owns privileged ground truth, hidden evaluation, configuration, and recordings. Keep the repository minimal and environment authoring easy.

## Accepted design
- Python/MuJoCo core; reconstructed projects contain MJCF and assets representing the reset state.
- Versioned JSON request/response protocol; bring-your-own agent and harness in a rootless OCI container, with a scripted example and client.
- Actions: observe, grasp a camera pixel, move the grasp by world displacement, release, reset, submit. Only one grasp exists at once.
- Ideal point attachment transmits force without a direct torque constraint. No jaw size, robot arm, workspace limit, or force cap. Configurable numerical softness; replaceable grasp implementation later.
- RGB, depth, and camera calibration disclosure independently configurable. Default RGB and calibration; camera remains fixed.
- Simulation advances only for action ticks. Cumulative ticks and active wall time survive reset. Hidden evaluation pauses agent wall-time accounting. Future budgets remain extensible; broker tokens can be counted when available.
- No agent network, credentials, host files, or privileged state. Optional host inference broker forwards to one configured endpoint. Fail closed without the required container isolation.
- Explicit submissions create immutable snapshots. Validate bounded asset bundles and reject traversal, plugins, and external references. Load untrusted models in isolated resource-limited workers.
- Score reset appearance and time-aligned held-out interaction rollouts, independently of the live simulation. Report RGB/depth/silhouette discrepancies and explicit probe failures. Optional privileged parameter metrics use declared correspondence, including surface sliding-friction coefficient. Scores remain researcher-only; agent sees validation results.
- Surface friction can be inferred through dragging/release motion despite an ideal attachment. Behavioral equivalence does not imply uniquely identified parameters; distinguish material coefficients from effective MuJoCo contact friction.
- Starter environments: block on table and spring/damped hinged object. New environments need scene XML and a short TOML manifest; bespoke metrics may use trusted hooks.
- Log run configuration, events, budgets, submission snapshots, metrics, private probe artifacts, and interaction video sampled in simulation time. Split videos at resets and retain partial results on failure.

## Validation and delivery
Test interactions, observations, reset determinism, budgets, malformed requests/submissions, fidelity perturbations, and complete scripted runs. Verify isolation and playable videos on a compatible container host. Runtime access was unavailable in the initial session; disclose checks that cannot run. Keep setup, protocol, authoring, and development continuity docs. Commit only when the active user request authorizes it.

## 2026-10-28 addendum — configured experiments and Astra pilot

Experiment control now uses one private store: `experiments/configs/` for native
TOML plus small typed research metadata, `experiments/runs/<id>/` for each attempt,
and a generated multi-experiment dashboard. Prepared runs copy their environment
into private `source/`; requested physical values are actual MJCF edits there,
with text intent and resolved source hashes recorded. No natural-language
parameter parser or general configuration framework is introduced.

Researchers select appearance, dynamics, reconstruction, optional correspondence
parameters and hinge metrics through configuration. Disabled families skip work.
The pilot selects appearance/dynamics/reconstruction, avoiding hidden-name
requirements for geometry-matched density and COM. Researcher parameter text,
source XML, manifests and evaluation values never enter the public task; explicit
model constraints are public instructions rather than claims of enforcement.

The strict API preset uses exactly `gpt-6-astra`, a host Responses broker, optional
contact wrench observations and a hard 1800-second wall budget that includes
preflight, initialization, inference and private evaluation. Active time remains
separate. Public agent commentary and provider-returned summaries are timestamped
and labeled; hidden reasoning is neither requested nor represented.

The repository supplies local run/view skills and a dashboard for recorded
metrics, public progress and exact archived frames. Read-only viewing does not
advance simulation or call a model. Prepared/blocked/partial/failed outcomes and
trusted fixtures remain distinct from completed isolated runs. A controlled
fixture is never a substitute for a pilot.

A strict OCI pilot may start only after current trusted-image inspection, actual resource
verification and credential presence checks. Missing credentials or unenforced
CPU/memory limits are explicit blockers, not reasons to use a host agent or
another model. Final build, validation and the actual attempt run on Slurm's
`test` partition, with fresh image inspection on the same compute host.


Subsequent pilot steering selected spawned-agent development first and retained
the API preset for later. This explicitly named `development_shared_filesystem`
mode requires `--development`, uses the same public action protocol and logs, and
does not claim OS privacy isolation. A fresh model agent receives only curated
public paths by instruction; workspace access is still shared. The parent
orchestrator must stop that independently spawned agent at the native Slurm
controller deadline. It is not a silent fallback from failed OCI verification.

Validation after implementation: Slurm `test` job `56066912` passed 149 tests
with one OCI skip in 82.76 seconds. The first real prepared development flow
exposed an NFS `.nfs` file guard failure. A narrow regular-file, non-symlink
hexadecimal `.nfs` exception then passed 15 focused preparation/start/development
checks in job `56069922` (24.26 seconds). The full suite predates this fix.
Job `56063002` built and inspected the trusted image; no private project,
experiment, repository or credential payloads were present. Its effective
`memory.max=max` and `cpu.max=max 100000` block the Podman-cgroup backends; the
later `slurm_step` backend passed OCI integration in job `57174710`.
These validation jobs did not constitute an Astra pilot or isolated integration.

The later explicitly authorized development pilot
`astra-development-20261028-002` did complete: its public RPC ended with
`agent_finish` after 1698.70 seconds, three accepted checkpoints and 3000
physics ticks; Slurm job `56069945` completed postprocessing successfully.
Its external Astra agent was spawned without inherited private history and
returned a final report. The shared filesystem remained accessible, so this
result carries no OCI isolation claim. Per-checkpoint scores and source values
remain private experiment artifacts. The strict API preset remains unrun here.
