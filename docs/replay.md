# Exact recorded visual replay

The researcher audit records complete boundary wire bytes, including invalid requests, inference prompts/responses and submission content. It also records resolved actions, world identity, before/after tick accounting, outcomes, private state snapshots, camera observations and confirmed partial progress. These files are private: the agent must never mount the run directory.

`AuditLog(run_dir, max_bytes=512*1024*1024)` stores `audit/manifest.json`, an ordered hash-chained `audit/events.jsonl`, and SHA-256 addressed `audit/blobs/`. Raw `wire_b64`, RGB/depth PNG bytes and state JSON are stored as blobs. A separate attachment table allows lossless hydration without interpreting marker-shaped user JSON. `read_audit(run_dir)` verifies the chain, final manifest anchor, blob sizes/hashes and path bounds. Hashes detect corruption; they do not authenticate a log against someone able to rewrite the entire private run directory.

Before dispatching a potentially mutating action, the runtime reserves enough capacity for every permitted tick, checkpoint and outcome with `token = audit.reserve(bytes)`. It durably records the request and `action_begin` before mutation, then records progress and `action_end` using `audit.record(event, reservation=token)`. One token supports multiple records; `audit.release(token)` returns unused capacity. Reservations cannot silently grow after mutation. Exhausted budgets fail before dispatch; persistence errors stop execution explicitly. Every record is flushed and fsynced before acknowledgement. The byte limit covers durable audit content, not unrelated video/evaluation artifacts or temporary filesystem bookkeeping. A storage-device failure can still stop a running action; previously acknowledged records remain verifiable.

`replay_run(run_dir, output_dir)` verifies the complete audit before creating an empty output directory. It produces `index.html`, `timeline.json`, `frames.json`, `replay.json`, and byte-for-byte PNG/wire copies plus JSON state snapshots. Open `index.html` to scrub recorded observations for reference and candidate worlds together. The timeline retains original event JSON, sequence/hash references, world/episode/tick metadata, exact wire-file paths and explicit failure outcomes. No language model, external service, evaluator, simulation, renderer or submitted XML is executed during replay. Malformed or non-JSON boundary bytes are retained as binary wire artifacts.

Replay reproduces **recorded visuals**, not a cross-hardware physics resimulation. Every recorded camera frame is copied exactly; it does not interpolate or invent unrecorded intermediate frames. Confirmed terminal/partial frames are retained. If a candidate process dies with an unacknowledged in-flight tick, only the last durably confirmed state/frame is available, and the runtime records the uncertainty and conservative charged tick count. An interrupted action can therefore end with an explicit pending `action_begin` and confirmed partial snapshots.

Explicit submission/source/archive payloads and base64 image data URLs are also content addressed when canonically encoded; their original JSON values hydrate exactly. Recorded video events provide a safe relative `.mp4` path, size and SHA-256 after the writer closes. Replay verifies these references before output and copies the encoded videos without decoding to `videos/<original-relative-path>`, retaining the world and checksum in `replay.json`. PNG frames remain the exact visual replay source. Declared snapshot and RGB/depth checksums are independently checked against hydrated event payloads; snapshot checksums use sorted-key compact JSON with finite numbers.

The viewer annotates each frame with the most recent resolved action, its arguments/target, final outcome and tick range. A compact action list links to exact request wires; a separate boundary-record list exposes prompts, model replies and submission wires without embedding their payloads in HTML. Full event JSON remains in `timeline.json`. Verified MP4s appear as video controls labeled by world and episode/segment. The PNG frame inspector intentionally steps at a fixed 10 frames/second; this inspection rate does not claim to reproduce simulation or wall-clock timing. The byte-identical encoded videos preserve their original frame rate.

Replay uses two streaming audit passes. The first verifies every referenced blob, declared checksum, video and final chain anchor before creating output. The second writes the full hydrated timeline incrementally to a temporary file, flushes/fsyncs it and atomically renames it. Host memory retains one event at a time plus compact frame/action/video/link metadata, rather than retaining all hydrated payloads; repeated deduplicated submission or image references therefore do not expand into a run-sized in-memory timeline. Individual audit blobs are limited to 128 MiB during verification, and index records are read with a 4096-byte bound. Output disk usage may exceed the compressed/deduplicated audit because exact wire/image copies and the complete hydrated timeline are exported.
